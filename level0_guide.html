1 Use of the Level-0 Library

This guide describes level 0 of stdlib_NetCDF: the nc_* routines, one for each nf90_* procedure of netcdf-fortran 4.6.2 (plus nc_inq_unlimdims, which netcdf-fortran lacks), and the NC_* constants. Everything is available through

use stdlib_NetCDF

Each nc_<name> takes the arguments of nf90_<name>, in the same order, and is a subroutine with a trailing optional err argument instead of a function returning an integer status (see Error Handling). Data and attributes go through generic interfaces over the integer and real kinds of stdlib_kinds (int8, int16, int32, int64, sp, dp) and character data, at ranks 0 to 7.

You can use a small subset of the library for most tasks. The sections below show the usual sequences of calls, indented to show which calls happen between which. Level 1 of stdlib_NetCDF (netcdf_file, netcdf_variable) builds the same sequences into one-line calls; it is described in docs/API.md.

1.1 Creating a NetCDF Dataset

Here is a typical sequence of calls used to create a new netCDF dataset:

nc_create              ! create the dataset: enter define mode
    nc_def_dim         ! define dimensions: from name and length
    nc_def_var         ! define variables: from name, type, dimensions
    nc_put_att         ! assign attribute values
nc_enddef              ! end definitions: leave define mode
    nc_put_var         ! provide values for variables
nc_close               ! close: save the new dataset

Only one call is needed to create a dataset, and in define mode dimensions, variables and attributes may be defined in any order, as long as a dimension exists before a variable uses it. nc_def_dim and nc_def_var return the IDs that the following calls use.

Example

Create new.nc with a 2-D variable and its attributes:

use stdlib_NetCDF
use stdlib_kinds, only: dp
implicit none
integer :: ncid, x_dimid, y_dimid, varid
real(dp) :: data(6, 12)

call random_number(data)
! NC_CLOBBER: create, overwriting the file if it exists
call nc_create("new.nc", NC_CLOBBER, ncid)
call nc_def_dim(ncid, "x", 6, x_dimid)
call nc_def_dim(ncid, "y", 12, y_dimid)
! NC_DOUBLE: the netCDF type of 64-bit reals
call nc_def_var(ncid, "data", NC_DOUBLE, varid, dimids=[x_dimid, y_dimid])
call nc_put_att(ncid, varid, "units", "m")
! NC_GLOBAL: a global attribute, of the dataset rather than of a variable
call nc_put_att(ncid, NC_GLOBAL, "title", "a new dataset")
call nc_enddef(ncid)
call nc_put_var(ncid, varid, data)
call nc_close(ncid)

1.2 Reading a NetCDF Dataset with Known Names

When the names of the dimensions, variables and attributes are known, the usual sequence is:

nc_open                    ! open an existing dataset
    nc_inq_dimid           ! get dimension IDs
    nc_inq_varid           ! get variable IDs
    nc_get_att             ! get attribute values
    nc_get_var             ! get values of variables
nc_close                   ! close the dataset

A dataset is opened in data mode. Dimension lengths, needed to size the arrays read, come from nc_inquire_dimension.

Example

Read the variable rh of foo.nc and its units attribute:

use stdlib_NetCDF
use stdlib_kinds, only: dp
implicit none
integer :: ncid, varid, lon_dimid, nlon, lat_dimid, nlat, time_dimid, ntime
real(dp), allocatable :: rh(:, :, :)
character(len=32) :: units

call nc_open("foo.nc", NC_NOWRITE, ncid)          ! NC_NOWRITE: open read-only
call nc_inq_dimid(ncid, "lon", lon_dimid)
call nc_inquire_dimension(ncid, lon_dimid, len=nlon)
call nc_inq_dimid(ncid, "lat", lat_dimid)
call nc_inquire_dimension(ncid, lat_dimid, len=nlat)
call nc_inq_dimid(ncid, "time", time_dimid)
call nc_inquire_dimension(ncid, time_dimid, len=ntime)
allocate(rh(nlon, nlat, ntime))
call nc_inq_varid(ncid, "rh", varid)
units = ""
call nc_get_att(ncid, varid, "units", units)
call nc_get_var(ncid, varid, rh)
call nc_close(ncid)

1.3 Reading a NetCDF Dataset with Unknown Names

A generic application (a dump tool, a converter) learns what a dataset contains from it:

nc_open                            ! open the dataset
    nc_inquire                     ! numbers of dimensions, variables, attributes; unlimited dimension
        nc_inq_dimids              ! the dimension IDs
        nc_inquire_dimension       ! name and length of each
        nc_inq_varids              ! the variable IDs
        nc_inquire_variable        ! name, type, dimensions, number of attributes of each
            nc_inq_attname         ! attribute names, by number
            nc_inquire_attribute   ! type and length of each attribute
            nc_get_att             ! attribute values
            nc_get_var             ! variable values
nc_close                           ! close the dataset

Dimension and variable IDs are 1, 2, 3, ... in definition order; attribute numbers are 1, 2, 3, ... for each variable (and for NC_GLOBAL).

Example

List the variables of foo.nc with their types and numbers of dimensions:

use stdlib_NetCDF
implicit none
integer :: ncid, nvars, i, xtype, ndims
! NC_MAX_VARS: the most variables a dataset may have, so the list fits
integer :: varids(NC_MAX_VARS)
! NC_MAX_NAME: the longest name netCDF allows, so any name fits
character(len=NC_MAX_NAME) :: name

call nc_open("foo.nc", NC_NOWRITE, ncid)          ! NC_NOWRITE: open read-only
call nc_inq_varids(ncid, nvars, varids)
do i = 1, nvars
    call nc_inquire_variable(ncid, varids(i), name=name, xtype=xtype, ndims=ndims)
    print "(a, ': type ', i0, ', ', i0, ' dimension(s)')", trim(name), xtype, ndims
end do
call nc_close(ncid)

1.4 Writing Data in an Existing NetCDF Dataset

With no new definitions, an existing dataset is opened for writing and written in data mode:

nc_open              ! open the dataset with NC_WRITE
    nc_inq_varid     ! get variable IDs
    nc_put_var       ! provide new values for variables, if any
    nc_put_att       ! provide new values for attributes, if any
nc_close             ! close the dataset

An attribute that grows needs define mode on a classic-format dataset (see the next section).

Example

Append a third record of rh to foo.nc:

use stdlib_NetCDF
use stdlib_kinds, only: dp
implicit none
integer :: ncid, varid
real(dp) :: field(10, 5)

field = 42.0_dp
call nc_open("foo.nc", NC_WRITE, ncid)            ! NC_WRITE: open for reading and writing
call nc_inq_varid(ncid, "rh", varid)
call nc_put_var(ncid, varid, field, start=[1, 1, 3], count=[10, 5, 1])
call nc_close(ncid)

1.5 Adding New Dimensions, Variables, Attributes

An existing dataset can be extended by reentering define mode:

nc_open              ! open the dataset with NC_WRITE
    nc_redef         ! put it into define mode
        nc_def_dim   ! define additional dimensions (if any)
        nc_def_var   ! define additional variables (if any)
        nc_put_att   ! define other attributes (if any)
    nc_enddef        ! check definitions, leave define mode
    nc_put_var       ! provide values for the new variables
nc_close             ! close the dataset

On a classic-format dataset, leaving define mode after changes may move the data of every variable; NetCDF-4 datasets are not affected, and accept new definitions even in data mode (the library switches by itself).

Example

Add a variable pressure(lon, lat) to foo.nc:

use stdlib_NetCDF
use stdlib_kinds, only: sp
implicit none
integer :: ncid, lon_dimid, lat_dimid, varid
real(sp) :: p(10, 5)

p = 1013.25_sp
call nc_open("foo.nc", NC_WRITE, ncid)            ! NC_WRITE: open for reading and writing
call nc_redef(ncid)
call nc_inq_dimid(ncid, "lon", lon_dimid)
call nc_inq_dimid(ncid, "lat", lat_dimid)
! NC_FLOAT: the netCDF type of 32-bit reals
call nc_def_var(ncid, "pressure", NC_FLOAT, varid, dimids=[lon_dimid, lat_dimid])
call nc_put_att(ncid, varid, "units", "hPa")
call nc_enddef(ncid)
call nc_put_var(ncid, varid, p)
call nc_close(ncid)

1.6 Error Handling

Every routine takes a trailing optional argument err of class state_type (from stdlib's stdlib_error), in place of the integer status that the nf90_* functions return.

  • err absent (the simplest use): a failure is first reported to the active report sink of stdlib_report (by default stdlib's global_logger, if it has log units; change it with set_report_sink), then the program stops with the NetCDF message, which ends with the symbolic status code: NetCDF: Variable not found (NC_ENOTVAR = -49).
  • err present: the outcome is returned in it and the program continues; nothing is reported. A type(state_type) gets stdlib's flag, message and location (state is STDLIB_IO_ERROR for any NetCDF failure; test it with err%ok() / err%error()).
  • type(nc_state_type) (extends state_type) also gets the NetCDF status in err%nc_status, NC_NOERR after a success, to branch on specific errors.

Pass err by keyword (err=err) when the routine has optional arguments before it (for example nc_create, nc_open, nc_inquire, nc_def_var, nc_put_var). The message of a status code is nc_strerror(status), its symbolic name nc_status_name(status).

Example

Look for a variable that may not exist, and react to that case only:

use stdlib_NetCDF
implicit none
integer :: ncid, varid
type(nc_state_type) :: err

call nc_open("foo.nc", NC_NOWRITE, ncid)          ! NC_NOWRITE: open read-only
call nc_inq_varid(ncid, "salinity", varid, err)
! NC_ENOTVAR: the status when no variable has that name
if (err%nc_status == NC_ENOTVAR) then
    print "(a)", "no salinity in this file: " // trim(err%message)
else if (err%error()) then
    error stop trim(err%message)
end if
call nc_close(ncid)

1.7 Compiling and Linking with the Library

stdlib_NetCDF is an fpm package; a project uses it as a dependency:

[dependencies]
stdlib_NetCDF = { git = "...", tag = "..." }   # or { path = "../stdlib_NetCDF" }

It links netcdff and netcdf, whose module and library directories fpm cannot find on its own. Pass them through the environment, for instance with Homebrew:

export FPM_FFLAGS="-I$(brew --prefix netcdf-fortran)/include -I$(brew --prefix netcdf)/include"
export FPM_LDFLAGS="-L$(brew --prefix netcdf-fortran)/lib -L$(brew --prefix netcdf)/lib"
fpm build

nf-config --fflags --flibs prints the right flags on other systems. What works depends on how netcdf-c and netcdf-fortran were built (nc-config --all): with Homebrew's netcdf 4.9.3 and netcdf-fortran 4.6.2, szip, quantization and HDF5 filters work, but Zstandard returns NC_ENOTBUILT and parallel I/O is unavailable. The routines still compile and report such failures through err.

1.8 Differences from the netcdf-fortran Interface

  • Names: nf90_<name> becomes nc_<name>, nf90_<constant> becomes NC_<CONSTANT>.
  • Subroutines with err instead of functions returning a status; see Error Handling.
  • Kinds: data and attributes use stdlib_kinds (int8 ... int64, sp, dp).
  • Rank-0 data (nc_put_var/nc_get_var of a scalar) accepts start but no count, stride or map, as netcdf-fortran's own scalar specifics.
  • nc_def_var takes every storage option of nf90_def_var and refuses them for a scalar variable (NC_EINVAL) instead of dropping them; nc_inquire_variable returns them all.
  • Routines calling netcdf-c directly, through bind(c): nc_inq_type, nc_create_mp and nc_open_mp (their netcdf-fortran 4.6.2 counterparts are broken), and nc_inq_unlimdims (absent from netcdf-fortran). They follow the Fortran conventions of the others (1-based IDs).
  • Not available (netcdf-fortran lacks them too): NC_STRING data (the type constant exists), in-memory datasets, per-variable chunk caches.

2 Datasets

2.1 Datasets Introduction

A netCDF dataset is a file (or, in NetCDF-4, a group hierarchy stored in one file) holding dimensions, variables and attributes. It is identified by its path when created or opened, and by a small integer, the NetCDF ID, afterwards.

A dataset is in one of two modes. In define mode dimensions, variables and attributes are created, renamed or deleted; in data mode variable values are read and written. A new dataset starts in define mode, an opened one in data mode; nc_redef and nc_enddef switch between them. NetCDF-4 datasets switch by themselves when needed, classic ones do not.

The formats, chosen at creation by the cmode flags:

  • classic (default): the original format, with a 2 GiB limit on some sizes;
  • 64-bit offset (NC_64BIT_OFFSET) and 64-bit data / CDF5 (NC_64BIT_DATA): classic model with larger limits;
  • NetCDF-4 (NC_NETCDF4): HDF5-based, with groups, user-defined types, compression, chunking, filters and several unlimited dimensions;
  • NetCDF-4 classic model (NC_NETCDF4 + NC_CLASSIC_MODEL): HDF5 storage restricted to the classic data model.

The routines of this chapter are in module stdlib_netcdf_file, except nc_strerror (stdlib_netcdf_error).

2.4 Create a Dataset: nc_create

nc_create creates a new netCDF dataset, returns its NetCDF ID, and leaves it open in define mode. The creation mode cmode combines flags with ior: NC_CLOBBER (the default: overwrite an existing file) or NC_NOCLOBBER (fail if it exists); the format, NC_64BIT_OFFSET, NC_64BIT_DATA, NC_NETCDF4, NC_NETCDF4 with NC_CLASSIC_MODEL; NC_SHARE for unbuffered access by concurrent readers; NC_DISKLESS to keep the dataset in memory only (it is not written to disk: netcdf-fortran has no NC_PERSIST, which netcdf-c needs for that).

The optional arguments tune the I/O; they are the same as nf90_create's.

Usage

subroutine nc_create(path, cmode, ncid, initialsize, chunksize, cache_size, cache_nelems, &
        cache_preemption, comm, info, err)
    character(len=*), intent(in)             :: path
    integer, intent(in)                      :: cmode
    integer, intent(out)                     :: ncid
    integer, intent(in), optional            :: initialsize
    integer, intent(inout), optional         :: chunksize
    integer, intent(in), optional            :: cache_size
    integer, intent(in), optional            :: cache_nelems
    integer, intent(in), optional            :: cache_preemption
    integer, intent(in), optional            :: comm
    integer, intent(in), optional            :: info
    class(state_type), intent(out), optional :: err
path

Name of the file to create.

cmode

Creation mode: NC_CLOBBER or NC_NOCLOBBER, combined with ior with format and other flags (see above).

ncid

Returned NetCDF ID of the dataset, used by every later call on it.

initialsize

Classic formats: initial size of the file in bytes.

chunksize

Classic formats: I/O buffer size hint in bytes; on return, the size actually used.

cache_size

NetCDF-4: size of the file's chunk cache, in bytes.

cache_nelems

NetCDF-4: number of slots of the chunk cache.

cache_preemption

NetCDF-4: preemption of the chunk cache, 0-100 (an integer here, a real in nc_open, as in netcdf-fortran).

comm

MPI communicator, for parallel I/O (needs a parallel build; see also nc_create_par).

info

MPI info object, for parallel I/O.

err

Optional error state (class(state_type), e.g. type(nc_state_type)). If present, the outcome is returned in it and the program continues; if absent, a failure is reported to the active report sink and the program stops. Pass it by keyword (err=err) when the routine has other optional arguments.

Errors

On success err (if present) is cleared, and an nc_state_type gets nc_status = NC_NOERR. On failure err holds the NetCDF message and, for an nc_state_type, the status code; without err the program reports and stops. Possible causes of errors include:

  • The file exists and NC_NOCLOBBER was given (NC_EEXIST).
  • The directory does not exist or is not writable (NC_EPERM or a system error).
  • Incompatible flags, e.g. NC_CLASSIC_MODEL without NC_NETCDF4 (NC_EINVAL).
  • A feature the library was built without, e.g. parallel I/O (NC_ENOTBUILT, NC_ENOPAR).

Example

Create a NetCDF-4 dataset create.nc, failing if it already exists:

use stdlib_NetCDF
implicit none
integer :: ncid
type(nc_state_type) :: err

call nc_delete("create.nc", err)          ! start clean; the error if it is missing is ignored
! NC_NETCDF4: NetCDF-4 (HDF5-based) format; NC_NOCLOBBER: fail if the file already exists
call nc_create("create.nc", ior(NC_NETCDF4, NC_NOCLOBBER), ncid, err=err)
if (err%error()) error stop trim(err%message)
call nc_close(ncid)

3 Groups

NetCDF-4 datasets can organise dimensions, variables, attributes and types in a tree of groups, like directories in a file system. The dataset itself is the root group, /; each group has a name, unique among its siblings, and a full name such as /forecast/ocean.

A group is identified by a group ID, which can be used wherever an nc_* routine takes ncid: a variable of group /forecast/ocean is defined, written and read through that group's ID. Dimensions are visible in the group that defines them and in all its descendants. Groups need a NetCDF-4 dataset created without NC_CLASSIC_MODEL.

The routines of this chapter are in module stdlib_netcdf_grp, except nc_inq_varids (stdlib_netcdf_var) and nc_inq_dimids (stdlib_netcdf_dim). The examples add groups to foo.nc, which is a NetCDF-4 dataset.

4 Dimensions

Dimensions are defined in define mode, before the variables that use them. A dimension has a name and a length; the length of an unlimited dimension (NC_UNLIMITED) grows as data is written along it, and is the number of records written so far. A classic-format dataset has at most one unlimited dimension, a NetCDF-4 dataset any number.

A dimension is referred to by its dimension ID: 1, 2, 3, ... in definition order. The name of a dimension can be changed later; its length cannot (other than by writing more records along an unlimited one).

In Fortran order, the first dimension of a variable varies fastest; the unlimited dimension, if any, must be the last (the slowest) in a classic dataset.

The routines of this chapter are in module stdlib_netcdf_dim. Listing the dimensions of a group is nc_inq_dimids, in Groups.

5 User Defined Data Types

NetCDF-4 datasets can define their own data types, in four classes:

  • compound: a record of named fields, each of a built-in or user-defined type, possibly an array (like a C struct or a Fortran derived type);
  • variable length (vlen): a ragged array, each element a sequence of any length of a base type;
  • opaque: a blob of a fixed number of bytes, which the library does not interpret;
  • enum: an integer base type whose values have names.

A user-defined type belongs to a group and is identified by a type ID, which can be used wherever a built-in type is (xtype of nc_def_var, of attributes, as a compound field type, ...). Types must be defined (and compound types completed) before use; once a variable or attribute uses a type, the type cannot be changed.

Data of user-defined types is moved as raw bytes by nc_put_var_any / nc_get_var_any and nc_put_att_any / nc_get_att_any: a character(len=*) buffer holding the values in the layout netCDF expects (for a compound, the field offsets given when it was defined, with the C alignment of each field). Build and decode such buffers with transfer.

Compound field IDs and enum member indices are 1-based, as in netcdf-fortran. nc_inq_type calls netcdf-c directly: netcdf-fortran 4.6.2's nf90_inq_type overflows its buffer and does not return the name. Writing vlen data needs the C layout of a vlen element (a length and a C pointer), which these wrappers do not provide; vlen types can be defined and inquired. The routines of this chapter are in module stdlib_netcdf_type.

call nc_get_var_any(ncid, varid, back, start=[1], count=[2])
print "(i0, 1x, f0.1)", transfer(back(17:20), 0_int32), transfer(back(25:32), 0.0_dp)   ! -3 10000000000.0

6 Variables

Variables hold the data of a dataset. A variable has a name, a type, a shape given by its dimensions (none for a scalar), and attributes. It is defined in define mode, and its values are written and read in data mode.

A variable is referred to by its variable ID: 1, 2, 3, ... in definition order (in a group, list them with nc_inq_varids). In Fortran, the first dimension varies fastest: a variable defined on [lon, lat, time] is read into an array a(nlon, nlat, ntime) and its records are the slices a(:, :, it). (ncdump and C list the same dimensions in the reverse order: rh(time, lat, lon).)

The routines of this chapter are in module stdlib_netcdf_var; nc_var_par_access is in Parallel I/O.

6.1 Language Types Corresponding to NetCDF External Data Types

The data routines (nc_put_var, nc_get_var, nc_put_att, nc_get_att, the fill-value routines) are generic over these Fortran types, which correspond to the netCDF types below. Values are converted between the Fortran type of the data and the external type of the variable on writing and reading (an out-of-range value gives NC_ERANGE).

Fortran type        netCDF type     size    default fill value
integer(int8)       NC_BYTE         1       NC_FILL_BYTE
character(len=*)    NC_CHAR         1       NC_FILL_CHAR
integer(int16)      NC_SHORT        2       NC_FILL_SHORT
integer(int32)      NC_INT          4       NC_FILL_INT
integer(int64)      NC_INT64        8       (no named constant; NetCDF-4 and CDF5 only)
real(sp)            NC_FLOAT        4       NC_FILL_FLOAT
real(dp)            NC_DOUBLE       8       NC_FILL_DOUBLE

The kinds come from stdlib_kinds. NetCDF-4 adds the unsigned types NC_UBYTE, NC_USHORT, NC_UINT, NC_UINT64 (read and written from signed Fortran integers), NC_STRING, and the user-defined types of chapter 5.

6.2 Create a Variable: nc_def_var

nc_def_var adds a variable to a dataset in define mode and returns its ID. Without dimids the variable is a scalar. The optional storage arguments, NetCDF-4 only, set at once what the nc_def_var_* routines below set one by one; they are refused for a scalar variable (NC_EINVAL), not silently dropped. As in netcdf-fortran, shuffle acts only together with deflate_level > 0.

    integer, intent(in), optional            :: endianness
    integer, intent(in), optional            :: cache_size

Errors

On success err (if present) is cleared, and an nc_state_type gets nc_status = NC_NOERR. On failure err holds the NetCDF message and, for an nc_state_type, the status code; without err the program reports and stops. Possible causes of errors include:

  • The dataset is not in define mode (NC_ENOTINDEFINE; NetCDF-4 switches by itself).
  • The name is already used by another variable (NC_ENAMEINUSE), or is not valid (NC_EBADNAME).
  • A dimension ID is not valid (NC_EBADDIM), or xtype is not a valid type (NC_EBADTYPE).
  • Storage options on a classic dataset (NC_ENOTNC4) or for a scalar (NC_EINVAL).
  • The unlimited dimension is not the last one, in a classic dataset (NC_EUNLIMPOS).
  • ncid does not refer to an open dataset (NC_EBADID).

Example

Define a compressed, chunked variable pressure(lon, lat, time) in foo.nc:

use stdlib_NetCDF
implicit none
integer :: ncid, lon, lat, time, varid

call nc_open("foo.nc", NC_WRITE, ncid)            ! NC_WRITE: open for reading and writing
call nc_redef(ncid)
call nc_inq_dimid(ncid, "lon", lon)
call nc_inq_dimid(ncid, "lat", lat)
call nc_inq_dimid(ncid, "time", time)
! NC_FLOAT: the netCDF type of 32-bit reals
call nc_def_var(ncid, "pressure", NC_FLOAT, varid, dimids=[lon, lat, time], &
                chunksizes=[10, 5, 1], deflate_level=4, shuffle=.true.)
call nc_enddef(ncid)
call nc_close(ncid)

6.6 Chunking: nc_def_var_chunking, nc_inq_var_chunking

6.17 Reading and Writing Character String Values

Classic netCDF has no string type: strings are stored in NC_CHAR variables, with the string length as an extra dimension, the first (fastest varying) in Fortran order. A rank-r array of character(len=n) values is an NC_CHAR variable with r+1 dimensions, the first of length n; a single string is a 1-D NC_CHAR variable. nc_put_var and nc_get_var accept character(len=*) data at ranks 0 to 7 and map it this way.

Strings shorter than the string dimension are padded on writing (with blanks from Fortran); read them into variables of the dimension's length and trim as needed. With start and count, the first element addresses characters within the strings.

The NetCDF-4 type NC_STRING (variable-length strings) is not supported by netcdf-fortran's data routines, nor by these wrappers.

Example

6.18 Fill Values

Unwritten values of a variable read as its fill value: the value of its _FillValue attribute if it has one, otherwise the default of its type (NC_FILL_BYTE, NC_FILL_CHAR, NC_FILL_SHORT, NC_FILL_INT, NC_FILL_FLOAT, NC_FILL_DOUBLE, ...). Readers can test for it to find missing data.

  • Set _FillValue before writing any data: with nc_def_var_fill, or as an attribute of the variable's type with nc_put_att.
  • Pre-filling costs a write of every value; turn it off per dataset with nc_set_fill (or per variable with nc_def_var_fill's no_fill) when all values will be written anyway.
  • nc_inq_var_fill returns the fill value in use.

7 Attributes

Attributes hold metadata: the units of a variable, its valid range, the title of a dataset. An attribute belongs to a variable, or is global (varid = NC_GLOBAL), and has a name, a type, and a length (one value, or a 1-D array; for text, the number of characters).

Attributes are created and changed in define mode (on a classic dataset; NetCDF-4 switches by itself), and read in either mode. They are identified by name; their numbers (1, 2, 3, ... for each variable) serve to list them. Conventions such as CF give standard names (units, long_name, standard_name, _FillValue, valid_range, scale_factor, ...).

The routines of this chapter are in module stdlib_netcdf_att; attributes of user-defined types are written and read as raw bytes with nc_put_att_any / nc_get_att_any (chapter 5).

8 Parallel I/O

With a netcdf built for MPI (nc-config --has-parallel reports yes), several MPI processes can open one dataset together and write or read parts of each variable: NetCDF-4 datasets through parallel HDF5, classic formats through PnetCDF. All the processes of the communicator make the define-mode calls with the same arguments; data calls may differ per process (each writes its own hyperslab).

The MPI handles (comm, info) are plain default integers, as in the mpi module, so stdlib_NetCDF itself has no MPI dependency: in an MPI program pass MPI_COMM_WORLD, MPI_INFO_NULL, and so on. Without a parallel build, these routines fail and report through err (Homebrew's netcdf has no MPI support; the examples below handle that case).

The legacy routines nc_create_mp, nc_open_mp, nc_set_base_pe and nc_inq_base_pe date from the Cray multi-processing interface; they work on any build and are kept for completeness. nc_create_mp and nc_open_mp call netcdf-c directly: netcdf-fortran 4.6.2 passes the base PE by address, so netcdf-c always fails with NC_EINVAL.

The routines of this chapter are in module stdlib_netcdf_par.

9.1 The Error State: nc_state_type

nc_state_type is the error state to pass as err when you need the NetCDF status code: it extends stdlib's state_type with nc_status, which every call sets, to NC_NOERR on success. A plain type(state_type) works too, with the stdlib fields only.

Usage

type, extends(state_type) :: nc_state_type
    integer :: nc_status = NC_NOERR
end type nc_state_type

! inherited from stdlib_error's state_type:
!   integer :: state                      STDLIB_SUCCESS, or STDLIB_IO_ERROR on any NetCDF failure
!   character(len=512) :: message         the NetCDF message with its symbolic code
!   character(len=...) :: where_at        the nc_* routine that failed
!   logical function ok(), error()        tests
!   function print()                      a one-line description
nc_status

NetCDF status of the last call made with this err: NC_NOERR or an NC_E* code.

state

stdlib's state: STDLIB_SUCCESS, or STDLIB_IO_ERROR for any NetCDF failure.

message

Message of the failure: the NetCDF text and the symbolic code.

where_at

Name of the nc_* routine that set the state.

Example

Handle a missing dimension, stop on anything else:

use stdlib_NetCDF
implicit none
integer :: ncid, dimid

call nc_open("foo.nc", NC_NOWRITE, ncid)          ! NC_NOWRITE: open read-only

select case (err%nc_status)
case (NC_NOERR)                                   ! NC_NOERR: the status of a successful call
    print "(a)", "found depth"
! NC_EBADDIM: the status when no dimension has that name
case (NC_EBADDIM)
    print "(a)", "no depth dimension: 2-D data"
case default
    error stop trim(err%message)
end select
call nc_close(ncid)
